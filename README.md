# 学习资料工作台 · Study Desk

> 一个本地优先（local-first）的个人学习资料工作台：集中存放、分类、检索学习文档，并内置一个**完全在浏览器里运行**的分析引擎，帮你提炼摘要、归纳主题、发现知识缺口、生成可执行的学习建议。

零依赖 · 零构建 · 无后端 · 不上传任何数据。

**线上地址**：https://whoaru-1.github.io/study-desk/
**本地地址**：http://127.0.0.1:4173 （`npm start`）

## 功能

### 总览
资料总数、主题标签、备份完整度、主题覆盖度四项指标；文件类型环图、主题分布条形图、最近更新、智能洞察摘要；侧边栏「资料健康度」（备份 / 覆盖 / 复习新鲜度）。

### 资料库
- **文件夹视图 / 列表视图**一键切换：文件夹视图按标签自动归类，每个标签一个文件夹，可折叠
- 拖拽或选择文件导入，也可直接粘贴文本
- **导入即解析**：`pdf / docx / pptx` 在本地运行时自动提取正文，导入完成的那一刻摘要、要点、关键词与资料卡摘要行就已生成
- 支持 `md / txt / html / csv / json / code` 正文解析（Markdown 标记会自动清洗）；解析失败（扫描件等）会标为「待提取正文」，详情里可点「提取正文」重试
- 标签筛选、关键词搜索（带上下文片段与命中高亮）、按更新 / 重要度 / 标题排序
- 资料行直接显示一句话摘要；资料详情面板：摘要、要点、关键词、标签增删（**可直接从已有标签中挑选**）、回溯原文、备份状态

### 标签
- 资料详情的标签输入支持**选择已有标签**：点输入框或右侧箭头展开列表，主标签在前、次标签紧随其后（带父级名），按使用量排序，输入即时过滤
- 输入新名称时可选择「创建为主标签」或「在「当前主标签」下创建次标签」
- 键盘可用：`↑↓` 选择、`Enter` 确认、`Esc` 收起

### 标签中心
- 统一的标签管理页：主标签与缩进的次标签并列展示，可新建、重命名、改色、换层级、删除、查看关联资料
- **持久化标签库**：用过的标签会一直保留（即使暂时没有资料使用），可标为「未使用」后批量清理（有次标签的主标签不会被清理）
- **每个标签可配置颜色**（12 个预设 + 自定义取色），颜色会同步到资料行胶囊、筛选条、文件夹图标、主题卡、关联图节点与总览条形图
- 底部「归类规则」卡片完整列出层级、文件夹映射与增删改的同步行为（见下方专节）

### 主标签 / 次标签与文件夹映射

**数据结构**

```js
state.tags = [{
  id: 't...',
  name: '索洛模型',        // 全局唯一（资料按名称引用标签）
  color: '#0a84ff',
  parentId: 'tm1',        // null = 主标签；非 null = 次标签，指向主标签 id
  createdAt, updatedAt
}]
```

- 资料仍然只存标签名数组 `doc.tags: string[]`，不存 id，因此改名需要批量改写（已在保存时处理）
- 文件夹不是实体，只是视图：`主标签 → 资料库/主标签`，`次标签 → 资料库/主标签/次标签`

**层级约束**

| 规则 | 表现 |
| --- | --- |
| 最多两级 | 次标签下不能再挂标签；给次标签新建子标签的入口不会出现 |
| 主标签可降级 | 没有次标签的主标签可以在设置里改成次标签（选一个父级） |
| 有次标签不可降级 | 该主标签的「次标签」选项被禁用，提示「已有次标签，不能改为次标签」 |
| 名称全局唯一 | 同名标签会被拦截；需要区分时用「主 / 次」或前缀命名 |
| 自愈 | 加载时若父标签已不存在，该标签自动升级为主标签；折叠状态按 id 保存，改名不失联 |

**文件夹与子文件夹的映射规则**

| 资料打标情况 | 归类结果 |
| --- | --- |
| 只打主标签 `经济增长` | `经济增长/` 根层（无次标签时直接列出；有次标签时归入「未归入次标签」分组） |
| 打主标签 + 次标签 `经济增长 · 索洛模型` | `经济增长/索洛模型/` |
| 只打次标签 `索洛模型` | 自动归到 `经济增长/索洛模型/`（不需要显式再打主标签） |
| 打多个主标签 | 默认同时出现在各个主文件夹中（视图复用，不复制文件）；切换「只归入第一个标签」后按 `doc.tags[0]` 唯一归属 |
| 第一个标签是次标签 | 「只归入第一个标签」模式下进入该次标签的子文件夹 |
| 完全没有标签 | `未归类` |

- 主文件夹显示总篇数（含所有子文件夹）与「N 个次标签」；子文件夹显示自己的篇数，空标签也会占位显示「空」
- 主/子文件夹都能单独折叠，状态按标签 id 持久化
- 侧栏与筛选条里点主标签会命中它下面所有次标签的资料；点次标签只命中该次标签
- 主题聚合时，次标签下的资料同时计入其主标签的主题覆盖度

**增删改的同步行为**

| 操作 | 资料 | 次标签 | 文件夹 |
| --- | --- | --- | --- |
| 主标签改名 | 所有 `doc.tags` 中的旧名批量改写 | `parentId` 不变，继续挂在这条主标签下 | 文件夹立即改名，子文件夹路径随之更新 |
| 次标签改名 | 同上 | 无 | 只改子文件夹名，主文件夹不变 |
| 主标签改色 | — | 不自动跟随（次标签可单独配色） | 主文件夹图标与胶囊换色 |
| 次标签换父级 | 资料标签不变 | `parentId` 改写 | 从旧主文件夹移到新主文件夹的子文件夹 |
| 次标签升为主标签 | 资料标签不变 | `parentId = null` | 子文件夹变成并列的主文件夹 |
| 删除次标签 | 仅从资料上解除该标签 | 无 | 子文件夹消失，主文件夹与其它子标签不受影响 |
| 删除主标签（无次标签） | 仅解除该标签 | 无 | 主文件夹消失 |
| 删除主标签（有次标签） | 解除主标签 | 二选一：**升为主标签**（保留子标签与资料）或**连同次标签一起删除**（子标签也解除） | 对应文件夹与子文件夹按选择处理 |
| 清理未使用标签 | 无影响 | 有次标签的主标签不会被清理 | 空文件夹被移除，带子标签的保留 |

> 删除任何标签都不会删资料；原件仍在 `~/Documents/StudyDesk`。

### 知识主题
按标签聚合出「核心主题」卡片（覆盖度环形进度 + 主题关键词 + 结构评级），以及长尾标签和全库关键词热度。

### 关键概念

**怎么判定**（纯规则，逐条可解释）：

1. **切分候选**：学科词表（经济增长、菲利普斯曲线、IS-LM…）最长匹配 → 命中即锁定为术语；对剩余文本切 2—6 字 n-gram 得到短语候选
2. **过滤**：停用字组合、格式词（习题/笔记/讲义）、泛化词（分析/影响/问题）；若某词几乎总被更长的词覆盖，判为碎片剔除
3. **四项打分**：`强度 = (1 + ln 词频) × IDF × 长度权重 × 来源权重`，术语额外 ×1.9，`IDF = ln(1 + 资料总数 / 含该词的资料数)`
4. **位置加权**：命中标题 ×1.16、标签 ×1.10、出现在开头 ×1.06（最多叠到 ×1.32）
5. **分级**：全库按强度排序，前 35%（至少 3 个）记为核心概念，其余为支撑概念；单篇内前 3 个也记为核心
6. **建索引**：同一概念跨资料合并，累计出现次数、覆盖篇数与共现关系

**怎么呈现**：

| 位置 | 形式 |
| --- | --- |
| 知识主题 → 关键概念 | 概念列表：排名、名称、核心/支撑、术语/短语、所属主标签、覆盖篇数、出现次数、强度条、前 3 个共现概念；可按全部/核心/支撑筛选 |
| 资料详情 | 「关键概念」胶囊，角标是本文出现次数，点一下跳到原文对应位置并高亮 |
| 概念详情 | 判定依据逐项列出（抽取方式 / 出现情况 / IDF / 综合强度 / 位置加权 / 分级）、原文摘录、关联概念、所属主题 |
| 判定规则 | 任意入口都能打开同一份规则说明，写清公式与阈值 |

**与原文的对应关系**：每个概念在每篇资料里保留最多 2 处上下文（前 26 字 + 概念 + 后 34 字），跨资料最多 4 条。原文高亮带 `data-term` 标记，点击概念或上下文片段会滚动到该词并做 1.8 秒橙色闪烁，因此「概念 → 原文」是可逆、可核对的，而不是黑盒输出。

### 知识图谱

**节点与关系**

| 类型 | 定义 | 视觉 |
| --- | --- | --- |
| 概念节点 | 去重后的关键概念，大小 = 综合强度，颜色 = 其主要来源资料的主标签 | 实心圆 |
| 概念关系 | 两个概念在同一篇资料中共同出现 → 一条边，权重 = `min(两词词频) + 核心概念加成(0.5/个)`，多篇重复出现会累加 | 线宽/透明度 = 权重 |
| 资料节点 | 资料图谱模式下的资料本身，大小 = 重要度 | 实心圆 |
| 资料关系 | 两篇资料共享概念（每次 1 分）或同一标签（1.5 分），≥1.5 才建边 | 线宽 = 权重 |

**组织方式**：先算概念共现矩阵 → 每个节点只保留最强的 3 条边（避免毛线团）→ 取强度最高的 30 个概念（移动端 18 个）→ 黄金角初始分布 + 斥力/弹簧/向心迭代布局 → 贪心放置标签，放不下就隐藏、悬停时显示。

**展示与交互**：

- 概念图谱 / 资料图谱一键切换，图例说明节点大小、连线含义与颜色规则
- 悬停：高亮邻居、淡化无关节点、跟随鼠标显示名称与指标
- 点击：概念节点 → 概念详情（判定依据 + 原文出处）；资料节点 → 资料详情
- 「只看核心概念」过滤、「重新布局」换一种排布
- 从概念详情点「在知识图谱中查看」，进入图谱并给该节点加高亮光环
- 下方两张卡列出「最强共现关系」与「枢纽概念」，可直接点开

**联动关系**：概念提取是图谱的数据源（节点 = 概念，边 = 共现），图谱是概念关系的空间化表达；图谱里点节点回到概念详情，概念详情里的原文片段回到资料原文。三者构成「原文 → 概念 → 图谱 → 原文」的闭环。

**典型场景**：复习前扫一遍核心概念清单自测；写作业时点概念直接跳到定义原文；看图谱找孤立概念（缺连接 = 理解断层）和枢纽概念（连接多 = 应当优先掌握）；考前按概念共现强度安排串联复习。

## 本地运行

需要 Node.js ≥ 16（仅用于起静态服务器，项目本身无依赖）。

```bash
cd 工作台制作
npm start
# → http://127.0.0.1:4173
```

或者不用 npm：

```bash
node server.js          # 默认 4173
PORT=8080 node server.js
```

macOS 也可以直接双击 `start.command`。

> 服务器只监听 `127.0.0.1`，不会暴露给同网段的其它设备。

### 原件存放在哪

用 `npm start` 启动时，导入的原始文件会被**复制一份**到访达可见的目录：

```
~/Documents/StudyDesk/
```

资料详情里因此多了「原始文件」卡片：

| 按钮 | 行为 |
| --- | --- |
| **在访达中显示** | 调用 `open -R`，在访达里选中该文件（等价于右键「在访达中显示」） |
| **打开** | 调用 `open`，用系统默认应用打开原件 |
| **打开资料文件夹** | 出现在空状态与备份页，直接打开 `~/Documents/StudyDesk` |

想换目录：`STUDYDESK_VAULT=~/某个目录 npm start`。

### 正文提取（导入即生成摘要）

导入文件时，`server.js` 会把仓库里的原件解析成文字，再交给前端分析引擎：

| 格式 | 实现 | 说明 |
| --- | --- | --- |
| PDF | macOS 系统自带的 PDFKit（经 `osascript -l JavaScript` 调用） | 无需安装任何依赖；非 macOS 退化为 `zlib` + 文本操作符的粗略提取 |
| DOCX / PPTX | 自带 zip 解包（`zlib.inflateRawSync`）+ XML 文本抽取 | 保留段落结构，按幻灯片顺序拼接 |
| TXT / MD / CSV… | 直接按 UTF-8 读取 | — |

提取结果按「路径 + 大小 + 修改时间」缓存在内存中；单次解析通常 100—300ms（80 页 PDF 约 15,000 字）。

- 解析失败（扫描件、纯图片）不会生成假摘要，而是标记为「待提取正文」，详情里可点「提取正文」重试
- 本地启动时会自动补齐此前导入、还没解析过的资料（每次最多 12 份，失败过的不会反复重试）
- 线上模式（GitHub Pages）没有本地服务，这两步会提示用 `npm start`

> **为什么必须本地运行**：浏览器的沙箱禁止网页调用访达/系统打开文件，也不允许读取任意本地路径，`file://` 与 GitHub Pages 都做不到。这些能力依赖 `server.js` 提供的 `/api/reveal`、`/api/files`、`/api/extract`。在线上访问时按钮会自动退回「查看原文」（滚动到正文），并在空状态提示用 `npm start`。
>
> 安全边界：接口只监听 `127.0.0.1`，并校验 `Host` 头必须是本机；`rel` 参数会被限制在仓库目录内，`../` 之类路径一律拒绝。

也可以直接双击 `index.html` 用 `file://` 打开——功能完全一致，只是没有本地服务器。

## 部署到 GitHub Pages

推送到 `main` 后，仓库自带的 Actions 工作流（`.github/workflows/deploy.yml`）会自动构建并发布：

1. 打开仓库 **Settings → Pages**

4. 访问 `https://<用户名>.github.io/<仓库名>/`

首次发布后如果 404，等 1—2 分钟或重新运行一次 workflow。

## 分析引擎是怎么工作的

全部在本地、纯规则可解释，不调用任何模型接口：

1. **分词**：领域词表最长匹配 → 掩码已识别片段 → 对剩余文本做 2—6 字 n-gram
2. **过滤**：去掉格式类标签（`习题`、`笔记`…）和泛化词（`分析`、`影响`…），再用「更长词组频次覆盖」剔除碎片
3. **摘要**：句子打分 = TF-IDF 权重和 × 位置权重 × 长度惩罚；TLDR 从开头 8 句里挑「命中关键词且长度 ≥ 18 字」的最高分句（避免把封面语、插图对白当成结论），其余高分句作要点
4. **概念**：关键词 + 位置权重 + 原文片段 → 每篇 8 个概念；跨资料合并成概念索引，记录覆盖篇数、出现次数、所属主标签与共现关系
5. **主题**：按标签聚合，次标签下的资料同时计入其主标签；覆盖度 = 资料数量 + 类型多样性 + 复习新鲜度加权
6. **缺口**：未归类 / 长尾 / 标签重叠（Jaccard ≥ 0.8）/ 缺练习 / 久未复习 / 未备份 / 孤立概念
7. **标签注册表**：`state.tags` 保存 `{id, name, color, parentId}`，从旧数据加载时自动补登记、去重、校验颜色与层级（父级失效的次标签自动升级）；资料只存标签名，改名时批量改写，因此文件夹、筛选与统计会自动跟随
8. **建议**：由缺口与主题状态组合生成，带依据、场景、优先级与步骤
9. **图谱**：概念共现 / 资料共享概念建边，每个节点保留最强 3 条边，黄金角初始布局 + 斥力/弹簧/向心迭代（≤14 个节点自动收紧），标签贪心放置、冲突则隐藏、悬停显示

想接真实大模型：替换 `js/engine.js` 暴露的 `Engine.analyze(docs)` 即可，界面层无需改动。

## 隐私

- 所有资料、摘要、标签只存在浏览器本地
- 无第三方脚本、无字体外链、无埋点、无网络请求
- `robots.txt` 默认禁止搜索引擎抓取；若希望公开索引，删除该文件即可
- 清空数据入口在「备份」页底部，会同时清理 `localStorage`

> 资料正文、标签、总结存在 `localStorage`；原始文件副本存在 `~/Documents/StudyDesk`。在资料库中删除一条记录**不会**删除原件，需要清理时直接到该文件夹操作。

> 注意：`localStorage` 与浏览器配置绑定。换设备 / 换浏览器 / 清理站点数据都会丢，重要资料请用「导出备份」保存 JSON。
